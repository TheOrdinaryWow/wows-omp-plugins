# roadmap

[English](README.md) | 简体中文

> 把项目路线图放进仓库，让每个会话都知道项目在做什么、做完了什么、下一步是什么。

一份计划或一张待办清单只管一件事，路线图管的是整个项目，跨越很多个会话。这个插件把路线图以 Markdown 保存在 `docs/roadmap/` 中：有目标的构建轮次、每一轮里带可检验完成标准的阶段、暂时搁置的 TODO，以及关闭每个阶段时留下的证据。代理每一轮都能看到当前状态；开始一个阶段时，它会拿到一份交接说明，里面有它需要的全部信息；关闭阶段时，每条完成标准都必须有证据。路线图背后的决策由 [adr 插件](../adr/README.zh.md) 以 ADR 的形式保存。

初次使用？[使用指南](GUIDE.zh.md) 会带你走完第一个项目。

## 安装

```bash
omp plugin install adr@wows-omp-plugins
omp plugin install roadmap@wows-omp-plugins
```

需要 OMP 18.17.0 或更高版本、一个 Git 仓库（本地 `git init` 就够了，不需要远程仓库），以及 roadmap 依赖的 [adr 插件](../adr/README.zh.md)。安装后开一个新会话。没有安装 adr 插件时，`/roadmap` 和 `/init-project` 会拒绝运行并提示你安装。

## 快速上手

1. 运行 `/init-project`。`docs/roadmap/` 必须还不存在；`docs/adr/` 可以不存在、为空，或者已经由 adr 插件管理。
2. 回答代理的问题：项目是做什么的；第一轮的目标、约束、非目标和原则；已经做出的决策；以及各个阶段的目标、范围、完成标准和依赖。
3. 查看预览，选择 `Write N files`。你确认之前不会写入任何内容。
4. 让代理开始一个阶段。它会拿到一份交接说明，包括这一轮的目标和边界，这个阶段的目标、范围、完成标准、TODO 和相关决策，前面几个阶段交付了什么，以及已经为它做好的计划。代理从这里开始规划工作。
5. 工作完成后，代理为每条完成标准附上证据，关闭这个阶段。这一轮的所有阶段都关闭或放弃之后，运行 `/roadmap close-round`。

随时可以用 `/roadmap` 打开路线图控制台。

## 用法

### 路线图里有什么

| 记录 | 是什么 |
| --- | --- |
| 轮次（`R1`） | 一个构建周期，有目标、约束、非目标，以及引用决策的原则。轮次的状态是 `planned`、`active`、`closed` 或 `dropped`；同一时间只有一个处于活跃状态。 |
| 阶段（`S01`） | 一块工作，有目标、范围和完成标准。它从 `planned` 到 `active` 再到 `closed`，或者被 `dropped`。只有它依赖的阶段都关闭后，它才能开始。 |
| 完成标准（`DC1`） | 阶段完成时什么必须成立，以及怎么检查。 |
| TODO（`T001`） | 先放一放、以后再做的工作，带有来源、严重度（`high`、`normal`、`low`），以及一个目标阶段或一个触发条件（比如“等我们接入支付时”）。 |
| ADR（`ADR-0001`） | 一条决策记录，由 adr 插件维护。轮次在原则中引用它们，阶段可以关联到它们。决策不会随着轮次结束而失效。 |

代理只能通过插件修改路线图文件，插件会保证它们前后一致；代理不能直接编辑这些文件。你自己仍然可以在编辑器里修改正文。轮次处于活跃状态时，代理每一轮都会看到一份简短的路线图状态，包括当前会话正在做哪个阶段。

### 做一个阶段

让代理开始一个阶段，会话就会绑定到这个阶段，代理也会拿到交接说明。如果阶段已经是活跃状态，会话会加入它，并提醒可能有另一个会话正在做。路线图状态会显示哪些阶段现在就能开始，哪些还在等其他阶段。

在 Plan Mode 中开始一个阶段，只是把交接说明交给代理用于规划；计划批准、开始实现时，阶段才真正开始。

如果活跃阶段的范围或完成标准需要调整，代理会记录一条带理由的修订。途中发现的其他工作记成 TODO，决策记成 ADR。在你提交之前，代理还可以更正或删除它最近的一条修订。

阶段尚未开始时，可以让代理把它移到另一个活跃或已规划的轮次，ID 和关联的 ADR 都不变。任何阶段都不能因这次移动而排到它的依赖或前置阶段之前，否则插件会拒绝。不能继续留在原轮次的 TODO 会一起迁移。活跃阶段不能移动，已关闭或已放弃的轮次也不能移入或移出阶段。

阶段只有在以下条件都满足时才能关闭：

- 每条现行的完成标准都有通过的证据，并写明实际使用的方法和简要说明；
- 所有指向这个阶段的未完成 TODO 都已解决或移到别处；
- 关联到这个阶段的决策没有还处于提议状态的。需要你先接受或拒绝它们。

插件只检查证据是否齐全，不检查证据是否属实；代理必须真的运行它报告的那些检查。已关闭的阶段不会重新打开。需要后续修正时，新增一个跟在它后面的阶段。

### 不在路线图上的工作

不是所有事情都需要一个阶段。代理发现某个请求和一个未完成的阶段有重叠时，会在每个阶段、每个会话里问你一次：是把它当作路线图的一部分来做，记为这个阶段的计划外工作（free work），还是当作无关的事情。计划外工作只是阶段上的一行记录，不代表它满足了任何完成标准。

### 关闭一轮，开始下一轮

`/roadmap close-round` 要求所有阶段都已关闭或放弃，并且文档没有错误。它会问你这一轮的目标完成得怎么样（`achieved`、`partial`、`not_achieved` 或 `cancelled`，再加一段总结），以及每个仍未完成的 TODO 怎么处理：`resolved` 并附上引用，`wontfix`（列入已知限制），或 `carried` 带到后面的轮次。指向已规划轮次中阶段的 TODO 会自动移过去。轮次关闭后，它的文件不会再改变。

之后用 `/roadmap new-round` 为下一轮做访谈，或者启用下一个已规划的轮次，还可以把早先轮次带过来的 TODO 一并带上。

### 提前规划

`/roadmap plan-round` 可以起草未来的轮次，不管当前有没有活跃轮次。`/roadmap plan-round R2` 用来修改活跃或已规划轮次的章程，需要你确认预览；它直接替换章程，不追加修订日志，也不重命名目录。只修改活跃轮次的章程会保留格式 1，添加目标日期才需要格式 2。代理可以往已规划的轮次里添加阶段；这些轮次按顺序启用，启用之前其中的阶段不能开始。

轮次和阶段可以设置目标日期（`YYYY-MM-DD`）。状态视图会把它显示在实际日期旁边，并标出超过目标日期仍未完成的工作。目标日期不会阻止任何操作。

`/roadmap drop-round R2 <reason>` 可以放弃一个不再需要的已规划轮次及其阶段，文件作为历史保留。在此之前，先移走或解决指向这些阶段的 TODO。

### 旧仓库

已规划轮次、目标日期和轮次结果需要格式 2，`/init-project` 会直接创建格式 2。每次进入会话时，如果 `docs/roadmap/` 下没有未提交的改动，插件就会自动把格式 1 的仓库升级到格式 2，只修改并提交 `docs/roadmap/README.md`，其他已暂存的改动仍留在暂存区。目录有改动时，插件不做任何修改。提交失败则恢复 README，并提示如何手动升级。

你也可以运行 `/roadmap upgrade`，或在第一次 `/roadmap plan-round` 的预览或关闭轮次时接受升级。已关闭的历史不会被改写。

### 确认文档改动

初始化路线图，以及对轮次的每一项改动（规划、开启、放弃、修改目标日期），都需要你执行一条命令并确认预览。你确认之后，插件会再检查一遍文件，预览过期则拒绝写入。取消则什么都不写。

### 命令

所有命令都在主会话中运行，支持补全子命令、阶段 ID 和轮次 ID。

| 命令 | 作用 |
| --- | --- |
| `/init-project` | 检查前提条件并开始初始化访谈。 |
| `/roadmap` | 打开路线图控制台。 |
| `/roadmap stage <id>` | 显示一个阶段及其交接说明，但不开始它。 |
| `/roadmap check [--fix]` | 检查文档是否一致；`--fix` 重建自动生成的表格。 |
| `/roadmap upgrade` | 把仓库升级到格式 2。 |
| `/roadmap plan-round [id]` | 起草已规划的轮次，或修改活跃、已规划轮次的章程。 |
| `/roadmap new-round` | 启用下一个已规划的轮次；没有已规划的轮次时新建一个。 |
| `/roadmap drop-round <id> <reason>` | 放弃一个已规划的轮次及其阶段。 |
| `/roadmap retarget <round-or-stage> <YYYY-MM-DD\|none>` | 设置或清除目标日期。 |
| `/roadmap close-round [outcome=<assessment>:<summary>] [<todo>=<disposition>[:<reference>] …]` | 关闭当前轮次。参数可以提前回答它要问的问题，例如 `outcome=partial:"checkout shipped, refunds moved" T001=resolved:abc1234 T002=wontfix:"out of scope" T003=carried`。 |
| `/roadmap overlap <stage> roadmap\|free\|unrelated [intent]` | 用命令回答“这是否属于路线图”的问题。 |
| `/roadmap confirm <token>` | 没有对话框可用时，用它确认预览。 |

### `/roadmap` 控制台

`/roadmap` 会占满终端。Tab 在阶段、轮次和未完成 TODO 之间切换，直接输入文字即可搜索列表。右侧显示选中项的完整信息：状态、日期、依赖、关联的决策、未完成的 TODO 和正文。安装了 omo-prometheus 时，还会显示每条完成标准由哪些计划覆盖。Enter 跳到相关的条目：从阶段跳到它的轮次，从轮次跳到它的阶段，从 TODO 跳到它的阶段。

| 按键 | 操作 |
| --- | --- |
| Shift+X | 关闭选中的活跃阶段（由代理完成）。 |
| Shift+R | 关闭当前轮次。 |
| Shift+N | 开启新轮次，或启用下一个已规划的轮次。 |
| Shift+P | 规划一个新轮次。 |
| Shift+E | 修改选中活跃或已规划轮次的章程。 |
| Shift+D | 放弃选中的已规划轮次。 |
| Shift+T | 修改选中轮次或阶段的目标日期。 |
| Shift+U | 升级格式 1 的仓库。 |
| Shift+C | 运行检查。 |
| Shift+O | 在本次会话中切换按依赖顺序或按 ID 顺序排列。 |
| Esc | 先清空搜索，再关闭控制台。 |

检查、关闭轮次、放弃轮次、修改目标日期和升级都直接在控制台里完成，控制台会回到同一个条目并显示一行结果。关闭阶段以及开启或规划轮次需要代理参与，所以控制台会关闭，你在聊天里继续。

在控制台中修改文档时，预览会在左边列出文件，右边显示选中的那个。空格在排版后的文本和原始文本之间切换，Shift+W 写入全部文件，Esc 什么都不写。在 [Tern](https://docs.stencil.so/tern/) 中，控制台和预览以原生面板打开，按钮提供同样的操作。

### 代理做了什么

代理通过 `roadmap_*` 工具读写路线图：查看状态、添加和修改阶段、开始和关闭阶段、管理 TODO、检查文档，以及就重叠的工作询问你。初始化路线图和改动轮次，只有在你运行对应命令并确认预览后才会发生。子代理也能使用这些工具，但从不向你提问。决策则通过 adr 插件的工具管理。

## 设置

为当前用户修改设置：

```bash
omp plugin config set wows-omp-plugin-roadmap uiMenu inline
omp plugin config set wows-omp-plugin-roadmap stageOrder id
omp plugin config list wows-omp-plugin-roadmap
```

只想在某个项目里改，就在该项目的 `.omp/plugin-overrides.json` 中写上：

```json
{ "settings": { "wows-omp-plugin-roadmap": { "stageOrder": "id" } } }
```

修改会在你下次使用 `/roadmap` 或代理下次读取路线图时生效。

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| `uiMenu` | `fullscreen` | `fullscreen` 打开上文介绍的控制台和预览；`inline` 改用小的选择菜单。只影响终端；无法识别的值按 `fullscreen` 处理。 |
| `stageOrder` | `dependency` | `dependency` 按执行顺序列出阶段：一个阶段排在它依赖的阶段之后，所以后来插在中间的阶段会出现在它该在的位置。`id` 按编号排列。这会影响控制台、命令补全和代理看到的状态。写进路线图文件的表格始终按 ID 顺序。 |

## 与其他插件配合

- **adr** 是必需的。它保存轮次引用、阶段关联的那些决策。
- **omo-prometheus**：会话处在某个阶段时做出的计划，就属于这个阶段。一个阶段可以由多个计划共同交付，每个计划用一行 `Roadmap criteria: DC1, DC3` 声明它负责的完成标准，Prometheus 会在你批准前检查这一行。阶段交接说明和控制台会显示每个计划的进度、哪些完成标准已被覆盖，并在计划批准后阶段又有变动时给出提示。计划完成时，代理会被提醒考虑关闭这个阶段，并拿到计划最终评审的结果作为证据。计划发现的范围外问题可以记成路线图的 TODO。阶段不会自动关闭。

## 已知限制

- 初始化需要一个全新的 `docs/roadmap/`。已有的路线图，或者有文件但不由 adr 插件管理的 `docs/adr/`，都无法接管。
- 已规划的轮次不能跳过或重新编号，放弃的轮次 ID 也不会再用。
- 只有代理注意到重叠时，才会询问你重叠的工作怎么处理。
- 防止直接修改的保护只能尽力而为，对 shell 命令尤其如此，它不是沙箱。
- 加入一个活跃阶段时会提醒有其他会话，但不会占用这个阶段。
- `/roadmap check` 只检查文档，不检查代码是否与文档一致。
- 涉及多个文件的修改不是全有或全无；被拒绝的预览里出现过的 ID 之后可能会被跳过。
- 同一仓库的不同克隆各自编号，ID 可能冲突。同一克隆的多个工作树共享编号。
- 在 Tern 中，控制台和预览保持同一尺寸，窗格在内部滚动，因此滚动窗格里的文字无法选中或复制。
