# roadmap

[English](README.md) | 简体中文

Roadmap 工具管理构建轮次、阶段、结转 TODO 和架构决策，记录项目应交付的内容，以及每个阶段关闭时所依据的证据。实施计划单独存放。

需要 OMP 18.3.5 或更高版本，以及 git 工作树。0.1.0 版本没有插件设置，也没有运行时依赖。

## 安装

```bash
omp plugin marketplace add TheOrdinaryWow/wows-omp-plugins
omp plugin install roadmap@wows-omp-plugins
```

安装后请启动新会话。插件包含 `roadmap` 判断技能和固定版本的 MADR 4.0 模板。

## 概念

| 记录 | 用途 |
| --- | --- |
| 轮次（`R1`） | 一个构建周期，包含目标、约束、非目标，以及引用 ADR 的原则。最多只能有一个活跃轮次。关闭后，其目录会原地冻结。 |
| 阶段（`S01`） | 包含目标、范围和可验证的完成标准。阶段从 `planned` 转为 `active`，再转为 `closed`，也可以被标记为 `dropped`。开始前，依赖阶段必须已关闭。 |
| 完成标准（`DC1`） | 说明必须通过的条件及验证方法。关闭阶段时，每一条当前标准都必须有通过证据。 |
| TODO（`T001`） | 延后处理的工作，包含来源、严重程度（`high`、`normal`、`low`），以及活跃轮次中尚未关闭的目标阶段或触发条件。每个轮次有一个 TODO 文档。 |
| ADR（`ADR-0001`） | 采用 MADR 格式的决策，包含考虑过的方案、决策结果，以及可选的 Confirmation。ADR 的生命周期不受轮次限制。 |
| 计划 | 根据阶段交接信息制定的实施步骤。计划不存放在 roadmap 目录中。 |

体系内工作会开始或加入一个阶段，并将会话绑定到该阶段。交接信息包括目标、范围、完成标准、指向该阶段的 TODO、引用的 ADR、自由工作日志和关闭指引。已关闭的阶段不会重新打开；修正工作应创建新阶段，并通过 `follows` 关联。

自由工作不会绑定会话。当主代理发现自由请求与尚未关闭的阶段重叠时，会调用 `roadmap_overlap`。你可以选择使用 roadmap、将请求记录为自由工作，或视为无关工作。同一会话中，针对该阶段保存的回答会被复用。选择自由工作只会在阶段的 Free-work log 中追加一行意图，不代表已经交付，也不表示满足了任何标准。后续规划仍须核实代码中已有的内容。

有活跃轮次时，插件会在每轮对话读取当前检出的文档，并向主代理和子代理上下文注入有长度限制的状态信息。阶段列表最多显示 12 项，其余内容可通过 `roadmap_status` 查看。没有活跃轮次时，不会注入这些状态，自由工作照常进行。在已初始化的仓库中，ADR 工具和受管文件保护仍然可用。

## 首次初始化与日常使用

1. 在主会话中运行 `/init-project`。仓库必须是 git 工作树，`docs/roadmap/` 必须不存在，`docs/adr/` 必须不存在或为空。
2. 回答代理的访谈问题：项目名称与说明；首个轮次的目标、约束、非目标和原则；已有决策；各阶段的目标、范围、完成标准和依赖。
3. 审阅 `roadmap_init` 展示的文件，并在写入前确认。预览编辑器中的文本看似可编辑，但其中的修改会被丢弃。如果草稿需要调整，请让代理修改工具输入。
4. 让代理调用 `roadmap_stage`，使用 `action: "start"` 开始阶段。根据返回的交接信息规划并执行工作。对已活跃阶段执行开始操作会加入该阶段，并提示其他会话可能也在处理它。
5. 使用 `amend` 记录活跃阶段的范围或标准变更，并说明原因。后续工作记入 TODO，决策记入 ADR。
6. 提供证据和处置结果后关闭阶段；所有阶段都已关闭或放弃后，再关闭轮次。

初始化和开启轮次都需要用户显式输入命令、主会话获得相应授权，并确认预览。确认后，插件会重新验证文件，拒绝过期预览。写入成功后，该授权即被消耗。无界面上下文无法回答预览、重叠处理或轮次关闭对话框；取消或无法取得回答都不构成写入授权。

### 关闭阶段

阶段只能从 `active` 状态关闭。代理调用 `roadmap_stage`，提供 `action: "close"`、阶段 `id`、`delivered` 交付摘要、可选的 `deviations`，以及：

- `evidence`：每条当前标准对应一项，包含 `criterion`、`result: "pass"`、实际使用的 `method` 和 `summary`；`commit` 可选。证据缺失或未通过时，关闭操作会被拒绝。
- `todos`：所有指向该阶段的开放 TODO 都必须以 `reference` 标记为 `resolved`，或 `moved` 到另一个有效目标。移动后 TODO 仍保持开放。也可以通过目标形式 `trigger: <text>` 提供触发条件。
- `adrs`：与该阶段关联的所有拟议 ADR 都必须被标记为 `accepted` 或 `rejected`。子代理不能作出这些决策；主会话必须先完成处置，子代理才能关闭阶段。

操作会记录 Outcome 和关闭哈希。插件会验证证据条目，但无法核实其中声明是否属实。代理必须实际执行所述检查，并报告真实结果。

### 关闭轮次与结转

`/roadmap close-round` 要求所有阶段都已关闭或放弃，并且文档检查没有错误。对话框会要求为每个开放 TODO 指定处置方式：提供引用并标记为 `resolved`；以 `wontfix` 记入 Known limitations；或标记为 `carried`，留待后续轮次考虑。关闭操作会原地冻结目录，不会移动目录。

对话框只授权关闭打开前审阅过的轮次及其文件快照。从状态菜单关闭时，审阅从菜单显示的时刻开始，而不是从选择 Close round 的时刻开始。如果菜单或处置对话框尚未结束时，该轮次已关闭、另一个轮次已开启，或轮次中的任何文件发生变化，关闭操作会因快照过期而被拒绝，且不写入文件。请重新运行 `/roadmap close-round`，审阅当前状态。

`/roadmap new-round` 会通过访谈收集下一轮次的章程。生成的 `roadmap_round_open` 预览可以从冻结轮次中导入选定的结转 TODO ID。导入项会获得新 ID，保留来源，并以触发条件开始，而不是沿用过期的目标阶段。旧轮次保持不变。

## 命令

以下命令都要求在主会话中运行。阶段 ID 支持参数补全。

| 命令 | 行为 |
| --- | --- |
| `/init-project` | 检查初始化前提，授予初始化权限，并开始访谈。 |
| `/roadmap` | 打开状态菜单，显示阶段、TODO 数量和有效操作。Close stage 会展示带证据关卡的 `roadmap_stage` 关闭工具指引，不会写入文件。 |
| `/roadmap stage <id>` | 显示完整阶段文档和规划交接信息，不会开始或绑定阶段。 |
| `/roadmap check` | 检查文档一致性。 |
| `/roadmap check --fix` | 重新生成符合条件的生成块，绝不修改人工编写的正文或冻结轮次。 |
| `/roadmap new-round` | 要求没有活跃轮次且检查无错误，然后授予开启下一轮次的权限并开始访谈。 |
| `/roadmap close-round` | 收集 TODO 处置结果，在所有阶段结束后冻结活跃轮次。 |

## 工具

这些是代理工具，不是斜杠命令。修改工具使用写入审批；`roadmap_status` 使用读取审批。

| 工具 | 输入或操作 |
| --- | --- |
| `roadmap_status` | 不带参数时显示轮次、阶段，以及按目标或触发条件组织的开放 TODO；可选 `stage` 用于查看完整详情和交接信息。 |
| `roadmap_stage` | `add`、`edit`、`amend`、`start`、`close`、`drop`、`renumber`。 |
| `roadmap_todo` | `add`、`update`、`resolve`、`move`。 |
| `roadmap_adr` | `create`、`revise`、`set_status`、`supersede`、`note`。 |
| `roadmap_check` | 可选 `fix: true` 会重新生成符合条件的生成块。检查文档，不检查代码与文档是否偏离。 |
| `roadmap_overlap` | 输入 `stage` 和 `intent`；阶段已绑定时，直接返回体系内工作状态及交接信息，不显示对话框，也不记录自由工作条目，无界面环境下亦如此。否则，主会话每个阶段只询问用户一次，之后复用回答。子代理不会发起询问。 |
| `roadmap_init` | 输入 `project`、`round`、初始 `adrs` 和 `stages`；要求 `/init-project` 授权及已确认的预览。 |
| `roadmap_round_open` | 输入 `round` 章程和 `import_todos` ID；要求 `/roadmap new-round` 授权及已确认的预览。 |

### 阶段操作

| 操作 | 规则 |
| --- | --- |
| `add` | 在活跃轮次中创建计划阶段。提供 `title`、`objective`、`scope_in`、`scope_out`，以及包含 `statement` 和 `verify` 的 `done_criteria` 条目；依赖和设计约束可选。 |
| `edit` | 替换计划阶段中提供的字段。阶段活跃后请使用 `amend`。 |
| `amend` | 向活跃阶段追加带日期的变更记录，必须提供 `reason`。`amendments` 可添加、修改或移除标准，也可添加或移除范围内外的条目。 |
| `start` | 要求依赖已关闭且检查无错误，然后激活并绑定阶段，返回规划交接信息。同一操作用于加入已活跃阶段时，不会修改其文档。 |
| `close` | 执行上述证据和 TODO/ADR 关卡检查，记录 Outcome 并冻结阶段。 |
| `drop` | 放弃计划或活跃阶段，必须提供 `reason`。须先解决或移动所有指向它的开放 TODO。 |
| `renumber` | 使用 `new_id` 为计划阶段重新编号，并更新可变引用。如果已关闭历史中包含必须修改的引用，则拒绝操作。 |

### TODO 和 ADR 操作

TODO 的 `add` 要求 `title`、`source`、`severity`，以及 `target` 或 `trigger` 之一；`body` 可选。`update` 修改活跃轮次中开放条目的指定字段。`resolve` 要求 `reference`。`move` 替换目标或触发条件，若目标阶段已关闭则拒绝操作。

工具管理的正文仅支持一小部分 Markdown：普通段落、条目文本均为单行的平铺无序或有序列表，以及完整闭合的顶层围栏代码块。无序列表标记为 `-`、`+` 或 `*`；有序列表标记由一到九位数字后接 `.` 或 `)` 组成。标记后使用一个空格。不支持嵌套列表和缩进的列表续行。允许普通标点，包括 `~20%`、`snake_case`、`quantity * unit price` 这样的乘法、带下划线或波浪号的 URL，以及 `x < y` 或 `x > y` 这样的比较。`<` 紧接 ASCII 字母、`/`、`!` 或 `?` 时会被拒绝，因为这可能开始 HTML、自动链接、注释或处理指令；行首不能是 `>`。允许行内强调分隔符，配对的分隔符可能被渲染为格式。代码之外仍不支持方括号、反斜杠转义和表格竖线。允许同一行内的代码片段；每组起始反引号必须在同一行以等长反引号闭合。跨行片段不能隐藏另一行的 HTML 或围栏。请将不支持的字面语法放入代码中，或使用 `&lt;script&gt;` 这样的实体。

围栏使用至少三个反引号或波浪号，前面可有零到三个空格。可选的信息字符串只能是一个语言标记，由 ASCII 字母、数字、`_`、`+`、`.` 或 `-` 组成。闭合围栏须使用相同标记，长度不短于起始围栏，前面可有零到三个空格，后面只能有空格或制表符，且不能带信息字符串。围栏内容按字面处理，可以包含其他位置不支持的语法。围栏不能从列表或引用内部开始。列表之后，应使用无缩进围栏；或先以空行分隔，再写一个无缩进普通段落，之后才能使用缩进围栏。此规则也适用于 TODO 正文前面的元数据列表。列表后的普通段落必须用空行分隔；不支持惰性列表续行。

在围栏和同一行代码片段之外，原始 HTML 和注释、Markdown 链接和引用定义、ATX 和 Setext 标题、块引用、表格、分隔线、缩进代码、制表符、格式错误或未闭合的围栏，以及有歧义的结构，都会在任何受管内容发生变化前被拒绝，并给出修复提示。工具提供的范围条目、标准说明、验证方法及其他单行字段遵循相同的标点和行内规则，但不能包含列表或围栏。工具还会重新解析渲染后的文档，确保预期的 ID、元数据、正文边界和固定标题保持不变。

ADR 的 `create` 要求 `title` 和 `sections`，其中须包含 `context`、非空的 `options` 和 `outcome`。可选章节包括 `drivers`、`consequences`、`confirmation`、`pros_cons` 和 `more_info`；还支持参与者列表和阶段关联。随插件提供的 MADR 4.0 模板包含 Confirmation 章节，没有实施检查清单。

`revise` 替换拟议 ADR 的整个正文，同时保留元数据；也可以更改标题。已接受的 ADR 不能通过 `revise` 重写。主会话可以使用 `set_status` 将状态设为 `accepted`、`rejected` 或 `deprecated`，或使用 `supersede`，以新接受的后继 ADR 替代已接受或已弃用的 ADR，并建立双向链接。`note` 在 More Information 下追加带日期的 `text`。无论请求的最终状态是什么，子代理只能创建拟议 ADR，不能设置状态或替代 ADR。

如果已有 ADR 的结尾处于未闭合围栏内，`note` 会拒绝操作，且不修改文档。请在编辑器中修复已存储的文件，或修改新备注以符合允许的正文语法，然后重试；工具绝不会通过重写已接受的正文来修复它。

## 受管文件保护

初始化后，工具调用钩子会在主会话和子代理会话中保护 `docs/roadmap/**` 和 `docs/adr/**`。它会查找目标所属的 git 工作树，同时检查词法路径和解析后的路径，包括悬空符号链接的目标，并阻止操作，提示改用 roadmap 工具。对于已有文件目标，还会按设备号和 inode 与会话及目标工作树中具有多个硬链接的受管文件进行比较，因此原生 `write` 和 `edit` 无法通过仓库内外的硬链接别名修改受管原文件。原生路径使用宿主的规范化规则，处理带 `@` 前缀的绝对路径、多余的 `:` 前缀、以主目录为基准的 `~` 路径和 `file://` URL。没有初始化标记的仓库不受影响。钩子中发生验证、路径解析或文件身份检查错误时，会拒绝调用，而不会放行可能绕过管理的修改。

| 接口 | 覆盖范围 |
| --- | --- |
| `write` | 其 `path`，包括从读取结果复制的 `[path#TAG]` 头和已有硬链接别名。 |
| `edit`、`apply_patch` | 每次原生 `edit` 调用都会从 `hashline`、`replace`、`patch`、`apply_patch` 和 `sloppy` 语法中推导目标路径；`apply_patch` 使用自己的语法。任何受管源路径、目标路径或已有硬链接别名都会被阻止。未知语法或模式会被拒绝。 |
| `ast_edit` | `paths` 使用原生作用域辅助函数：去掉首尾空白、移除外层双引号、展开由分隔符分开的条目、规范化反斜杠分隔符，然后推导目录或 glob。无效作用域会被拒绝。覆盖范围包括工作树外但包含受管根目录的目录，以及第一个 glob 路径段的上级目录。`docs/roadm*/**/*.ts` 推导为 `docs`；`/work/re*/docs/roadmap/*.ts` 推导为 `/work`，当前仓库位于其下时会被阻止。 |
| `lsp` | 通过 `file` 指定文件的 `rename` 和实际应用的 `code_actions`；通过 `file` 与 `new_name` 指定的 `rename_file`。符号重命名的 `new_name` 是标识符，不是文件系统路径。这并不表示会检查跨文件工作区编辑中的每个文件。 |
| `bash` | 尽力静态检测重定向（`>`、`>>`）、`tee`、`mv`、`cp`、`rm`、原地修改的 `sed` 和 `truncate` 后的路径参数。 |

这类工作流保护不提供文件系统沙箱。它不会拦截 `eval`、`ctx_execute*`、从 bash 启动的编辑器，或任意写文件的程序。Shell 变量、替换和间接写入可能绕过 bash 静态匹配。宽泛的目录或 glob 候选也可能被保守地阻止。

硬链接身份检查覆盖已存在且明确命名的文件目标。它不会枚举藏在无关目录或 glob 中的别名，也不会预测后续 shell 语句将创建的链接：必须能推导出目标文件名，而且文件已经存在，才能比较 inode。

你自己的编辑器不会被拦截。可以编辑人工编写的正文，但须保留 front matter、受管注释、固定标题和生成块分隔符。`check` 会将已存储内容中不支持的 HTML、引用定义、Setext 标题或分隔线、引用、容器内围栏和有歧义的缩进报告为不可自动修复的结构错误，并提示使用编辑器修复；它不会模拟这些内容的 CommonMark 行为。查找固定标题时，会屏蔽已闭合的顶层围栏，未闭合围栏也属于结构错误。工具会拒绝格式错误的结构，修改已关闭阶段或冻结轮次会被哈希检查发现。修正工作应使用新阶段，不要重写已关闭的历史。

只要关闭哈希仍被保留，就会验证它，即使当前状态已经改变。与保留的关闭元数据矛盾的状态也属于错误。生成块修复和文档修改都会拒绝这些完整性错误；请通过 git 恢复受影响的历史，而不是手动重新打开。

## 恢复与 git 工作树

写入使用一个仓库锁，并以原子方式替换每个文件。多文件操作不是全有或全无的事务。中断后，可能留下各自完整的文件，但生成索引过期，或整个操作只完成了一部分。

取消会在下一次临时写入或重命名前停止，并删除未提交的临时文件；已经完成替换的文件会保留。被取消的操作会报告这些文件和恢复指引。即使第一个文件已经完成替换，也不会绑定阶段、消耗预览授权或持久化重叠处理回答。重试前请检查并修复部分完成的操作。

1. 运行 `/roadmap check` 或 `roadmap_check` 检查目录树。
2. 对过期生成块使用 `/roadmap check --fix`，或调用 `roadmap_check` 并设置 `fix: true`。这不会修复人工编写的内容、重新计算历史关闭哈希或修改冻结轮次。
3. 通过 git 恢复其他损坏，然后再次执行文档检查。

按照项目规则提交变更后的文档。每个分支都以当前检出的 Markdown 为事实来源。工作树仅共享 git common directory 下 `roadmap/` 中的锁和带版本的 ID 计数器；新 ID 会高于存储计数器和磁盘上已有 ID。不同克隆不共享计数器，因此跨克隆冲突可以在合并时发现，但无法预防。

## 可选的 Prometheus 集成

将 [omo-prometheus](../omo-prometheus/README.zh.md) 与 roadmap 一起安装，即可规划并执行已绑定阶段。两个插件都不依赖对方，此集成也不受 `herdrDag` 设置控制。

1. 在 Prometheus 提案前开始或加入阶段。提案时，Prometheus 发出 `roadmap:binding-request`，roadmap 同步回复 `roadmap:binding`，两者的契约版本均为 `v: 1`。回复标识会话、请求、仓库、可信工具来源，以及可选的已绑定活跃阶段。没有同步回复表示 roadmap 未加载。
2. 新 Atlas 计划包写入版本 2 的 `approval.json`，其中可选的 `roadmapStage: { repoRoot, id }` 来自该提案绑定。版本 1 的批准记录仍可加载，不会重写其字节，也不要求重新批准。
3. 只有当 `roadmap_*` 工具的来源类型为扩展，且来源路径与握手中的 `toolSourcePath` 完全一致时，Atlas 才允许这些工具。其他扩展或 MCP 服务器提供的同名工具不适用此例外。
4. 某次账本写入首次使绑定计划完成后，Prometheus 会发出 `atlas:completed`，携带执行会话 ID、计划 ID、阶段，以及已验证的关卡结论和摘要。Roadmap 在该会话中保存待关闭条目；只要阶段仍活跃，就会在下一轮对话中添加提醒。
5. 执行会话将关卡结果映射到阶段标准，核实相关性，然后调用 `roadmap_stage`，使用 `action: "close"`。完成通知会发送提醒，不会自动关闭阶段。常规证据和处置关卡仍然适用。

要检查集成是否生效，可带阶段 ID 调用 `roadmap_status`，确认阶段处于活跃状态。开始或加入后，下一轮状态会显示 `Bound stage: S01`。对于拟议计划，请检查 Atlas 计划包中的 `approval.json`：`roadmapStage` 是计划携带绑定的持久化标记。完成后，执行会话会在下一轮上下文中收到 `Plan <id> completed for <stage>` 和关卡证据候选。仅安装两个插件，不会将未绑定的提案附加到阶段。

完成去重以每个 Prometheus 生产方实例为单位，不是持久化的恰好一次标记。重启生产方、重新打开已完成的账本行并再次完成计划，都可能再次发出 `atlas:completed`。Roadmap 在接收会话保留的状态中，按 `planId` 对待关闭条目去重；其他会话收到重复事件时，可能在那里创建提醒。

## 已知限制

- 0.1.0 不支持接管已有 roadmap 或 ADR 目录树。初始化要求全新的受管目录，以及不存在或为空的 ADR 目录。
- 重叠检测依赖主代理发现重叠并调用工具。它不是分类器，也不会自动将每个请求与每个阶段比较。
- Bash 保护只能尽力检测，并存在前文列出的其他缺口。它不会将代理置于沙箱中。
- 加入活跃阶段会提示其他会话可能在工作，但不会预留阶段，也不阻止并发实施。共享锁只串行化文档写入。
- 无法防止跨克隆 ID 冲突。即使工作树共享编号，检出的不同分支也可以有不同的 roadmap 状态。
- `check` 验证引用、元数据、生成块和关闭完整性，不验证代码是否满足文档。真实的关闭证据和边界检查仍然必不可少。
- 逐文件原子写入不提供整个操作的回滚。即使预览被拒绝，预览中的 ID 也可能已被消耗，因此编号可能存在空缺。
- 对话框需要交互式 UI。无界面执行无法提供确认或重叠处理回答。
- Atlas 完成提醒存在前文所述的按生产方和按会话去重限制。

以下格式说明复制自 `src/documents.ts` 中的 `HOW_THIS_DIRECTORY_WORKS`。初始化会将相同文本写入项目的 [docs/roadmap/README.md](../../docs/roadmap/README.md)，该文件同时作为初始化标记和生成索引。初始化前，该项目文件不存在。

## 此目录的工作方式

此目录记录结构化构建轮次、各轮次的阶段和结转 TODO。docs/adr/ 中的 ADR 记录决策，其生命周期不受轮次限制。计划描述实施步骤，不存放在这里。

根 README 是初始化标记和轮次索引。每个 NN-slug 轮次目录包含章程 README、TODO.md 和 stages/NN-slug.md。轮次使用 R1、R2 等编号；阶段使用 S01，TODO 使用 T001，ADR 使用 ADR-0001。阶段和 TODO 编号在所有轮次间全局递增，绝不复用。ADR 文件使用 NNNN-slug.md。slug 由小写 ASCII 字母、数字和连字符组成。

每个受管文件都有 format: 1 的 front matter 和 managed-by 注释。此 README 还包含 roadmap: { format: 1 }。Front matter 和固定标题属于结构。工具管理的正文允许普通段落、平铺文本列表和已闭合的顶层围栏，以及普通标点、纯文本 URL、行内强调和同一行代码片段；不支持结构性 Markdown、Markdown 链接和原始 HTML 语法。阶段标题为 Objective、Scope（In 和 Out）、Done criteria、可选的 Design constraints 和 Risks、Amendments、Free-work log，以及可选的 Outcome。轮次章程包含 Goal、Constraints、Non-goals、Principles、Stages 和 Known limitations。TODO 分为 Open 和 Closed in this round。ADR 正文遵循随插件提供的 MADR 4.0 模板，以 Confirmation 记录验证，实施步骤留给计划。

代理通过 roadmap_* 工具修改受管文件。用户可以在编辑器中编辑正文；工具写入前，必须先修复格式错误的结构。生成块使用 `<!-- roadmap:generated:<name> -->` 和 `<!-- /roadmap:generated -->` 标记。编号、元数据、标题和生成索引由工具管理。

轮次状态为 active 或 closed。阶段状态为 planned、active、closed 或 dropped。已关闭阶段不会重新打开；修正工作使用带 follows 的新阶段。阶段开始前，依赖必须已关闭。完成标准说明必须通过的条件和验证方法；关闭时记录证据、TODO 处置结果和 ADR 处置结果。开放 TODO 需要严重程度、来源，以及尚未关闭的目标阶段或触发条件。章程原则引用 ADR，而不是重复决策内容。已接受 ADR 通过状态转换、替代，以及带日期的仅追加备注进行变更。

已关闭阶段带有 closed_sha256；已关闭轮次带有 frozen_sha256，并作为只读历史保留。最多只能有一个活跃轮次。没有活跃轮次时，自由工作不受限制，也不会注入 roadmap 上下文；ADR 管理仍然可用。

写入使用一个仓库锁和逐文件原子替换。中断的多文件操作可能留下过期索引：运行 roadmap_check 或 /roadmap check，再使用 check --fix 重新生成生成块。Fix 绝不会修改人工编写的正文或已关闭轮次。其他损坏请通过 git 恢复。共享的 git common directory 只存储锁和带版本的 ID 计数器；每个分支都以当前检出的 Markdown 为事实来源。

Check 验证文档一致性。它无法判断代码是否实现了文档内容。关闭证据和边界检查有助于让二者保持一致。
