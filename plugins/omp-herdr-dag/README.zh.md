# omp-herdr-dag

[English](README.md) | 简体中文

在 Herdr 侧边窗格中实时显示原生待办、已批准计划的执行、Atlas 依赖关系和子代理活动。查看器只观察工作，不负责调度依赖、完成待办，也不会在子代理结束时修改 Atlas 账本。

## 安装

```bash
omp plugin install omp-herdr-dag@wows-omp-plugins
```

安装后请重启 OMP。需要 OMP 18.3.5 或更高版本、`PATH` 中可用的 `herdr` CLI，以及在 Herdr 内运行的交互式 OMP 会话。Linux 和 macOS 使用同一套实现，但 macOS 尚未验证。不支持 Windows，会显示一次提示。非交互式子会话不会启动查看器。

窗格需要 Bun 可执行文件。将 `bun` 加入 `PATH`，或将 `viewerRuntime` 设为其路径。自动发现先尝试 `bun`；只有宿主可执行文件的 `--version` 输出符合 Bun 的语义版本格式时，才会继续尝试它。插件不会假定编译后的 OMP 可执行文件能充当查看器运行时。缺少 Bun 时会警告并跳过窗格管理。

Herdr 提供 `HERDR_ENV=1`、`HERDR_PANE_ID` 和 `HERDR_SOCKET_PATH`，三者缺一不可。在 Herdr 外，`/dag-pane` 会提示窗格不可用。原生 `todo` 包装器仍会注册，在 Herdr 外也一样。

## 宿主模式

只有 `mode: "tui"`、`hasUI: true` 且三个 Herdr 环境变量齐全时，才会运行窗格管理、查看器、传输订阅和快照发布。RPC/rpc-ui 与 ACP 即使 `hasUI` 为 true，或继承了 Herdr 环境变量，也不会启动这些功能。`hasUI: false` 的 SDK/无界面会话绝不会启动或分割窗格；缺少 `HERDR_PANE_ID` 同样会阻止窗格启动。`/dag-pane [open|close|toggle]` 是 TUI 命令，没有无界面窗格替代命令。原生 `todo` 包装器在所有模式下仍可用，详见下文。

查看器不发布插件状态 sidecar：图形是原生待办/子代理状态和 Atlas 状态的投影，客户端可通过宿主 RPC 数据和 omo-prometheus 的 sidecar 获取来源状态。已有的 Herdr 快照只用于查看器恢复，不构成另一套工作流状态源。

## 命令与自动打开

```text
/dag-pane [open|close|toggle]
```

不带参数时切换开关状态。`open` 是幂等操作；没有窗格时执行 `close` 也安全。手动打开不受 `displayTiming` 限制。插件只管理自己记录的窗格 ID，不会通过标题查找并管理窗格。

自动打开遵循 `displayTiming`：

| 值 | 打开条件 |
| --- | --- |
| `never` | 不自动打开；请使用命令。 |
| `any-todo` | 存在原生待办、已批准计划的待办，或已绑定的 Atlas 计划。 |
| `plan-execution` | 存在经过验证的原生计划执行，或已绑定的 Atlas 计划。 |
| `atlas-only` | 仅在存在已绑定的 Atlas 计划时打开。 |

仅有子代理活动不会打开窗格。在查看器中按 `q` 或执行 `/dag-pane close` 会保存主动关闭状态。同一次运行的更新不会重新打开窗格。发现新的运行 ID，或执行 `/dag-pane open`，会清除该状态。`/new` 和会话切换会复用窗格，同时重新绑定其内容和存储。

## 数据来源与图形含义

| 来源 | 默认边框与标题颜色 | 含义 |
| --- | --- | --- |
| 原生待办 | 蓝色，`#4f8cff` | 原生阶段组成分层区域。虚线阶段分隔符表示顺序，不表示依赖。 |
| 原生计划执行 | 紫色，`#a371f7` | 经过验证的原生批准交接之后，首个非空的新待办列表。 |
| Atlas | 绿色，`#3fb950` | omo-prometheus 的任务、修正和最终关卡，以及账本依赖边和修正来源边。 |

计划执行需要已记录的提案、宿主中匹配的计划引用，以及完全匹配的批准封装。用户发送 `Plan approved.` 或仅收到新会话事件都不够。计划列表完成或被放弃，且代理轮次结束而不再继续时，本轮计划执行结束。之后出现的列表属于普通的蓝色待办运行。

排队的合成 developer 批准消息，与新轮次中的批准提示使用相同的检查。规范待办写入必须同时晚于实时轮询基线和已记录的批准，才能被认定为首个计划列表；启动、切换或回退时重放的历史列表不符合条件。在代理轮次最终结束的边界，插件先协调规范待办写入，再检查计划列表是否已进入终态。可信的排队交接通过宿主时间戳和批准文本识别，只接受发生在当前提案之后的交接，且每次交接只能消费一次。上下文中保留的旧批准不能批准同一路径下的后续提案。

Atlas 绑定期间，名称严格为 `Atlas tasks`、`Atlas fixes` 和 `Atlas final gates` 的镜像阶段会从原生待办视图中隐藏。完全由镜像组成的列表不能认领或消费已就绪的原生计划批准。Atlas 释放绑定或集成被禁用时，镜像会重新显示为普通蓝色待办；之后的新原生列表仍可认领该批准。

正向依赖使用颜色较淡的实线连接，使节点框比连线更醒目。所选节点的入边和出边会加粗，并改用本次运行的数据来源颜色。反向依赖仍然有效，使用点线连接，并在目标节点上标注 `↑ after <label>`。修正边使用点线。关键路径只沿显式依赖边计算，使用观察到的节点耗时；尚未启动的节点使用单位权重。关键路径以粗线绘制。经过其他连接线时，只有它自身的分支保持粗线；与选中高亮共用线段时，以关键路径为准。没有显式依赖边的运行没有关键路径。已完成的层可以折叠。

默认情况下，图中显示正向依赖的传递约简。如果一条更长的正向路径已经确定两个节点的先后顺序，就不再绘制它们之间的直接边。例如，依赖所有任务的最终关卡会作为一组扇出分支挂在最后一个任务下。修正边和反向边始终绘制，关键路径计算仍会考虑所有依赖。按 `e` 可绘制全部依赖，底栏始终列出所选节点的直接依赖（`deps: T4, T6, T7`）。长边按来源节点共用一条垂直主干，穿过跳过的层，再在各目标处分支。汇入同一节点的边共用一个箭头。

节点框宽度为 30 列；如果缩小后能让最宽的一层放入窗格，会缩至不低于 20 列。查看器支持平移并跟随选中节点，因此比窗格更宽的一层，只要不超过窗格宽度的两倍，或在较窄窗格中不超过 120 列，就仍保持单行。四个节点框需要 86 列，所以 50 列宽的窗格会将四个最终关卡放在同一行，并横向滚动到选中的关卡。只有更宽的层才会在自己的分层区域内换行，均匀分布，并保持通常的顺序：先从左到右，再从上到下。例如，50 列宽窗格中的八个节点框会排成两行，每行四个。通向后续行的主干从前面各行的中间向下穿过，不会绕到外侧。同一节点的多条出边或入边会在那里共用连接线。方向键在绘制出的节点框之间移动，翻页也遵循绘制顺序。折叠的层始终只占一行汇总。

每个节点位于其父节点位置中位数的下方，因此链条会垂直向下。`layoutAlign` 为 `centered`（默认值）时，原本会重叠的同级节点会在父节点两侧均匀展开，整张图以画布轴线居中；图能放入窗格时，该轴线就是窗格轴线。设为 `left` 时，重叠的同级节点只向右移动，整张图靠左边缘排列。

状态颜色来自 OMP 主题，与数据来源颜色相互独立：

| 图标 | 状态 | 颜色角色 |
| --- | --- | --- |
| `○` | 待处理 | Muted |
| `◐` | 运行中 | Accent |
| `✔` | 已完成 | Success |
| `✖` | 失败 | Error |
| `⊘` | 被阻塞 | Warning |
| `⊖` | 已放弃 | Dim |

运行中的节点如果关联了停滞的子代理，会使用警告色。运行中的任务卡片无论是否关联节点，也会使用警告色边框和 `stalled` 标签，直到收到新的进展。子代理失败不会将待办或账本行标记为失败或完成。

Tasks 视图显示来自原生 `task`、eval agents 和 workpool 的直接子代理：工具及参数、近期输出、模型、重试详情、耗时，以及宿主提供的 token 用量和费用。子代理启动时，会关联到当时正在进行的原生待办。同一子代理多次激活时，会保留已完成的用量并加上当前激活的用量，因此累计进度帧不会被重复计算。运行用量对每个关联子代理只计一次。不可用的指标显示缺失值标记，而不是零。

## 显式待办依赖

启用 `todoDependencies` 后，`todo` 在保留原生字段不变的同时，接受可选的 `edges`。任务内容必须逐字匹配。`task` 依赖 `after` 中的每个内容字符串：

```json
{
  "op": "init",
  "list": [
    { "phase": "Implementation", "items": ["Build parser", "Connect viewer"] },
    { "phase": "Verification", "items": ["Check rendered output"] }
  ],
  "edges": [
    { "task": "Connect viewer", "after": ["Build parser"] },
    { "task": "Check rendered output", "after": ["Connect viewer"] }
  ]
}
```

包装器会先移除 `edges`，再调用原生工具，保留原生修改、details、钩子、批准、批量失败处理和渲染行为。格式错误、引用未知任务、自引用或成环的依赖会被丢弃，并在结果文本中追加 `Herdr DAG edges:` 警告；成功的待办修改仍会生效。原生操作报错时不会记录依赖边。移除或修改任务会清理相关依赖边；`init` 开始新一代列表。插件不会根据措辞或阶段顺序推断依赖。关闭 `todoDependencies` 只会禁用依赖边处理，不会禁用原生待办操作。

## 设置

`omp plugin config` 使用的包名：`wows-omp-plugin-omp-herdr-dag`。

```bash
omp plugin config wows-omp-plugin-omp-herdr-dag
```

插件在启动、会话切换、每次命令和每次自动打开评估时，读取会话工作目录对应的设置，心跳评估也包括在内。无效字段各自回退到默认值，每个项目作用域只警告一次。下文的“下次启动”指关闭并重新打开查看器；修改设置不会重启已经运行的查看器。

| 设置 | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `displayTiming` | `never` \| `any-todo` \| `plan-execution` \| `atlas-only` | `plan-execution` | 自动打开策略；下次评估时生效，不会关闭现有窗格。 |
| `finishBehavior` | `close-with-omp` \| `keep-open` | `close-with-omp` | 宿主关闭时使用当前设置；查看器的心跳丢失策略在下次启动时确定。 |
| `landscapePosition` | `left` \| `right` \| `top` \| `bottom` | `right` | 横向布局的位置；下次打开或方向变化后重建时生效。 |
| `portraitPosition` | `left` \| `right` \| `top` \| `bottom` | `bottom` | 纵向布局的位置；下次打开或方向变化后重建时生效。 |
| `landscapeSize` | 0.15 到 0.6 之间的数字 | `0.35` | 横向布局中 DAG 所占比例；下次打开或方向变化后重建时生效。 |
| `portraitSize` | 0.15 到 0.6 之间的数字 | `0.4` | 纵向布局中 DAG 所占比例；下次打开或方向变化后重建时生效。 |
| `followOrientation` | 布尔值 | `true` | 允许在方向变化时重建；下次方向检查时生效。 |
| `focusPane` | 布尔值 | `false` | 创建查看器时将焦点移到查看器；下次打开或重建时生效。请参阅下文的交换限制。 |
| `stalledAfterSeconds` | 10 到 900 之间的数字 | `90` | 子代理多久没有进展后，将运行中的任务卡片及其关联的运行中节点标记为停滞；需重启 OMP 才能更新任务来源的阈值。 |
| `todoDependencies` | 布尔值 | `true` | 处理并持久化显式待办依赖边；设置重新加载后的工具调用生效。 |
| `atlasIntegration` | 布尔值 | `true` | 监听 Atlas 契约；重新加载时禁用或重新激活消费方，并调整镜像去重。 |
| `followTheme` | 布尔值 | `true` | 心跳时轮询 OMP 主题变化；关闭后保留最后一次采样的配色。 |
| `colorTodo` | 字符串（`#rrggbb`） | `#4f8cff` | 待办标题和边框颜色；重新加载后下次发布快照时生效。 |
| `colorPlan` | 字符串（`#rrggbb`） | `#a371f7` | 计划标题和边框颜色；重新加载后下次发布快照时生效。 |
| `colorAtlas` | 字符串（`#rrggbb`） | `#3fb950` | Atlas 标题和边框颜色；重新加载后下次发布快照时生效。 |
| `retentionDays` | 1 到 365 之间的数字 | `14` | 插件拥有的会话文件的保留期限；会话启动时执行清理。 |
| `layoutAlign` | `centered` \| `left` | `centered` | DAG 排列方式：树形图以窗格轴线居中，或紧凑靠左；重新加载后下次发布快照时生效。 |
| `viewerRuntime` | 字符串（可执行文件路径，留空则自动发现） | `""` | Bun 可执行文件；下次启动查看器时生效。 |

## 位置与结束行为

初始方向在 `cols < 2 * rows` 时为纵向，否则为横向。测量 OMP 矩形区域时，会加回插件拥有的 DAG 窗格所占部分，因此打开查看器本身不会导致方向变化。方向判断使用滞回区间：低于 `2 * rows - 4` 时从横向切为纵向，高于 `2 * rows + 4` 时从纵向切为横向。尺寸变化检查采用 750 ms 防抖，心跳也会请求检查。

Herdr 0.9.3 无法在同一标签页内移动窗格。方向变化时，插件只关闭自己记录的窗格，然后在配置的位置打开替代窗格，恢复持久化的视图状态和 socket 连接。替代窗格会获得新的窗格 ID。单独修改位置或尺寸不会重建已打开的窗格。

右侧和底部直接分割；左侧和顶部先分割，再交换位置。Herdr 会将焦点移到交换来源。设置 `focusPane: false` 时，插件会恢复通常的 OMP 焦点，但 CLI 无法恢复交换前任意一个无关窗格的焦点。

- `close-with-omp`：宿主关闭时关闭窗格。连续错过三次间隔 2 秒的心跳后，查看器会关闭自己的窗格并退出。
- `keep-open`：宿主关闭或心跳丢失后保留窗格，显示断开连接的横幅，并每秒重试 socket。恢复快照不能证明 OMP 仍在运行。

关闭流程会立即阻止后续窗格启动和尺寸调整计时器。窗格关闭、socket 清理和快照刷盘共用 1.8 秒的时限；尚未完成的 socket 启动保持取消状态，并执行清理，不会接受查看器连接或启动心跳。

重启时，如果插件拥有的窗格是为另一个 socket 启动的，或旧记录没有 socket 信息，会关闭并重建该窗格，使用当前查看器连接。通过 `q` 关闭的查看器在会话重新绑定后仍保持主动关闭状态；窗格不存在不会阻止传输层切换会话。

无论结束行为如何，按 `q` 始终会关闭查看器自己的窗格。如果在分割窗格之后、记录新窗格 ID 之前发生崩溃，可能留下孤立窗格。插件会发出警告，但绝不会通过标题查找或关闭窗格，因此请手动关闭该孤立窗格。

## 查看器按键

| 按键 | 操作 |
| --- | --- |
| `q`、Ctrl+C | 退出并关闭查看器自己的窗格。 |
| `t` | 切换 DAG 和 Tasks；在会话记录视图中，切到另一个主视图。 |
| `h` | 切换上一代待办列表的显示状态；只保留一代历史列表。 |
| `[` / `]` | 在 DAG 视图中选择上一次/下一次运行。 |
| Tab | 将 DAG 方向键在节点模式（默认，底栏标记 `NODES`）和平移模式（`PAN`）之间切换。 |
| 方向键、`j` / `k` | 节点模式：选择最近的已绘制节点。上/下选择上一行或下一行中中心位置最近的节点框；左/右选择同一行的下一个节点框。视图跟随选中节点。平移模式：将视图移动几行或几列，选中节点不变。Tasks：移动选择。会话记录：滚动。 |
| PgUp / PgDn | 在节点、任务或会话记录中翻页；平移模式下每次移动半屏。 |
| Enter | 展开或折叠所选节点或任务的详情。 |
| `c` | 切换所选运行中已完成层的折叠状态。 |
| `p` | 切换关键路径高亮。 |
| `e` | 显示所有直接依赖边。默认隐藏其顺序已由更长路径表示的边；底栏仍会列出所选节点的直接依赖。 |
| `f` | 选择下一个运行中的节点并滚动到该节点；反复按下会循环遍历所有运行中的节点。没有运行中节点时不执行操作。 |
| `o` | 打开所选任务的会话记录，或所选节点关联的子代理会话记录。 |
| Esc | 从会话记录返回，或关闭帮助。 |
| `?` | 切换帮助显示。 |

查看器运行时会开启终端鼠标事件上报，并在所有退出路径中关闭，包括收到信号时。滚轮可在两种模式下滚动 DAG，也可滚动 Tasks 列表和会话记录；Shift+滚轮或水平滚轮可横向滚动 DAG。单击节点会选中它，双击则像 `o` 一样打开其会话记录。平移或滚动会让 DAG 停止跟随选中节点，因此实时更新会保留当前滚动位置，直到通过节点模式方向键、翻页或点击重新选择节点。切换运行或视图时会从顶部开始，并跟随选择。所有操作也都能用键盘完成。模式、滚动位置和依赖边显示开关不会持久化。启用鼠标事件上报时，普通拖动不再选择窗格文本；大多数终端仍可在按住 Shift 时选择文本。

会话记录下钻会增量读取已有的子会话文件，显示助手文本、工具调用和简短的结果预览。它不会打开可写的宿主会话。用户文本和输出中的终端控制序列会被移除；标签按显示宽度换行。

## omo-prometheus 集成

安装 [omo-prometheus](../omo-prometheus/README.zh.md) 即可查看 Atlas 运行。本插件的 `atlasIntegration` 和生产方的 `herdrDag` 设置都必须启用，两者默认均为 `true`。没有启用的生产方时，查看器会提示 Atlas 集成不可用，但原生待办和 Tasks 仍可使用。

只用于观察的 `pi.events` 契约使用普通 JSON，包含 `v: 1` 和匹配的 `sessionId`：

| 事件 | 方向与载荷 |
| --- | --- |
| `herdr-dag:hello` | 消费方发送到生产方：会话 ID 和请求 ID。 |
| `atlas:hello` | 生产方是否可用；回复时原样返回请求 ID；可选的已绑定计划标识（`id`、`name`、`planFilePath`、`cwd`）。 |
| `atlas:snapshot` | 已绑定计划标识、账本状态及总计、带依赖/修正元数据的行、每行的子代理进展、最近 50 条时间线事件，以及时间戳。 |
| `atlas:released` | 已解除绑定的计划 ID 及原因：`exit`、`session-switch` 或 `shutdown`。 |

Hello 回复是同步的；如果已绑定计划，随后会发送快照。绑定和释放也会广播状态，因此启动顺序不影响使用。未知版本和其他会话的消息会被忽略。释放只表示从当前视图解除绑定，不表示工作已完成或子代理已取消。`herdrDag` 为 false 时，omo-prometheus 不会发出任何消息，包括 hello 回复；其账本、待办镜像、所有权和 UI 行为均不变。无需更改 Atlas 计划包格式。

## 本地存储与隐私

持久化文件位于 `ctx.sessionManager.getSessionDir()/herdr-dag/<sessionId>/` 下。文件采用带版本的 JSON，通过临时文件替换写入。`snapshot.json` 和 `pane.json` 使用版本 2，加载时会升级版本 1，保留恢复数据、所有权和主动关闭状态。缺少 socket 路径的 v1 窗格记录会保持连接未知，只重新启动自己记录的窗格，绝不会接管其他窗格。`view-state.json` 保持版本 1。未知版本或更新版本会被忽略并替换。允许存储的字段如下：

| 文件 | 存储字段 |
| --- | --- |
| `snapshot.json` | `version`、会话 ID/名称、代次、连接标记、时间戳、运行、任务卡片、主题配色、三种来源颜色、Atlas 可用性，以及可选的 `layoutAlign` 设置（旧快照中不存在，按居中方式渲染）。 |
| 运行对象 | ID、来源、标题、代次、节点、依赖边、创建/更新/完成时间戳，以及完成数/总数/耗时/token/费用统计。 |
| 节点对象 | ID、标签、状态、分层区域/名称、详情、开始/完成时间戳、代理、关联任务 ID 和停滞标记。依赖边包含 `from`、`to` 和 `kind`。 |
| 任务卡片 | ID、父任务/节点 ID、代理、状态、可选停滞标记、描述、当前工具/参数、近期输出、已完成/当前激活的总计、激活次数、模型、重试次数/上限/错误、会话记录路径、开始/完成时间戳、解除关联标记、深度和活动可用性标记。激活总计包含 token、费用和持续时间。 |
| 主题配色 | 文本、柔和、暗淡、强调、成功、错误、警告、边框、强调/柔和边框，以及可选的背景颜色。 |
| `pane.json` | `version`、分割中/已打开阶段、已知的窗格/标签页 ID、宿主窗格 ID、方向、位置、启动时间戳、可选的启动 socket 路径，以及主动关闭标记。 |
| `view-state.json` | `version`、已折叠运行 ID、视图（`dag`、`tasks`、`transcript`）、所选运行 ID，以及关键路径开关。 |

宿主会话也会存储自定义条目：`omp-herdr-dag:plan-execution` 包含 `v`、提案中/执行中/空闲状态、可选的计划路径/运行 ID，以及时间戳；`omp-herdr-dag:todo-edges` 包含 `v`、代次和 task/after 依赖记录。插件不收集凭据，但快照可能包含任务描述、工具参数、输出片段、错误消息和本地路径。请按会话数据对待这些文件。

实时传输使用私有目录下的 Unix socket，路径为 `os.tmpdir()/omp-herdr-dag/<hash>.sock`，以 Herdr 宿主窗格和进程 ID 生成标识。快照用于重启恢复，不用于实时传输。Socket 增量更新会合并发送；序列不匹配或积压过多时会进行完整重新同步。

会话启动时，`retentionDays` 会清理插件拥有的其他会话目录，条件是目录及文件中最新的修改时间早于保留期限。它绝不会清理当前会话、宿主会话记录、Atlas 计划包或宿主会话中的自定义条目。会话记录内容不会复制到这些文件中；查看器直接读取其已有路径。

## 已知限制

- 仅支持 Herdr，不提供独立终端窗格管理，也不支持 Windows。
- 孙级子代理的活动不会传到根会话的活动事件总线。通过注册表发现的后代代理只显示状态卡片，标注 `activity unavailable`，没有实时工具、输出或用量。
- 指标和会话记录是否可用取决于宿主提供的信息。子代理生命周期是活动证据，不是任务最终验收通过的证明。
- 依赖边只是显示元数据，绝不是调度器。阶段顺序不代表依赖关系。
- macOS 使用 Linux 的代码路径，但尚未在此验证。
