## 原生判定细化

宿主级联先验证完整窗口，每个窗口最多 8 KiB。这些窗口只确定候选区域，不代表精确匹配行。控制台随后对每个结果最多发送一次原生 judge 请求，每次搜索最多 20 次请求、256 个细分片段。每个文件最多分配 24 个片段；结果较多时，按确定性的平均配额限制。片段仅从已验证窗口中切出，每个片段最多包含 12 个完整行、1,536 个 UTF-8 字节。

请求包含 `search`、`file`、`passages` 映射和 `fullFile`。`passages` 使用 `s0`、`s1` 等键，并保留原始行号。完整预览未被截断且不超过 24 KiB 时，`fullFile` 包含全文，同时通过独立的 `whole` 概率问题判断文件的整体用途是否回答查询；否则该字段为 null，不发送整文件问题。只有基于完整文本得到 `whole >= 0.8` 时，才标记为 `scope: "whole-file"`，使用不带行号的路径引用，并且不高亮。这避免了仅凭抽样就宣称整个文件相关。

其他结果使用 `scope: "ranges"`，保留概率达到级联阈值 0.2 的片段，并合并相邻片段。预算外部分和单行超长部分保留原始验证窗口分数，并明确说明尚未细化。请求或读取失败、问题未回答时，保留原始窗口，记录 `refineFailed`，将覆盖标记为不完整，不会当作不匹配。细化与级联共用同一个仅限原生的 judge、缓存策略、用量账本和取消信号。

`ConsoleHit.ranges` 保留级联窗口；`ConsoleHit.refined` 是预览和引用使用的细化范围。整文件结果的细化范围为空。全文预览仍最多读取 4 MiB；预览截断提示与 judge 是否检查过全文是两个独立概念。

## 费用与缓存统计

插件只包装本次搜索传入的缓存引用，不修改进程级共享缓存。每次原生缓存查询将问题数计入 `total`，将实际返回的回答数计入 `cached`。状态显示为 `all cached`（N/N）、`partly cached`（k/N）或 `fresh`（0/N）。共享缓存不可用时显示 `cache unavailable`；`--no-cache` 不向 judge 传入缓存，完全禁用读取和写入，并显示 `cache off`。

费用独立于缓存状态：恰好为零显示 `$0`；正数且小于 0.0001 时显示 `<$0.0001`；其余费用使用四位有效数字，不补尾部零。

报告、对话框和进度中的英文数量标签仅在数量恰好为 1 时使用单数，如 `1 hit`、`1 file`、`1 request`，其他数量使用复数。

## 查询翻译

检测规则是：查询中至少包含一个文字系统不属于 Latin 的 Unicode 字母。因此中文、日文、西里尔文和阿拉伯文会触发翻译；带重音的拉丁字母、数字和标点本身不会触发。这是文字系统检测，不是通用语言分类；使用拉丁字母的非英文查询保持原样。

模型解析使用宿主 `@tiny` 角色及其候选池；tiny 缺失、失败或未返回英文查询时，再使用 `@smol`。本地推理模型使用通用 tiny chat 客户端，而非仅输出 20 个 token 的标题模式；在线模型通过 `completeSimple` 和注册表的凭据解析器调用。请求仅包含原始查询和英文代码搜索翻译指令，最多输出 128 个 token。取消信号继续传递；翻译不可用时会说明原因，并继续搜索原文。在线用量以 `find-translate` 记入账本，也计入报告费用，但不计入判定缓存回答数。

每次调用可用的 tiny 或 smol 模型前，进度会显示 `translating with <role>: <provider>/<model>`，明确标示正在等待的翻译角色和模型。

报告的 `query` 是实际搜索文本。翻译成功时增加 `originalQuery` 和 `translation: { model: "<role>: <provider>/<id>" }`；跳过或失败时增加 `translation: { skipped: "<reason>" }`。显示与历史记录始终使用原始查询。翻译不会修改宿主的角色设置。

发送给代理的已选结果消息同样保留原始查询、实际翻译查询和结果内搜索来源，不会因发送结果而丢失搜索范围的选择依据。

## 过滤

`--glob` 和 `--ext` 通过本次搜索独立的原生文件系统视图过滤目录项，在宿主级联列出文件或进行词法扫描前生效。共享文件系统不变，目录仍可遍历，忽略策略文件仍可读取。显式文件根路径在启动级联前检查。不含斜杠的 glob 匹配任意深度的文件名；含斜杠的 glob 匹配相对搜索根目录的路径。同类条件之间取并集，glob 与扩展名条件取交集。扩展名转成小写并去掉前导点。

`--min-score` 必须位于 [0.2, 1]，不降低宿主级联阈值。它在细化前过滤级联结果，在细化后过滤行范围。没有剩余行范围的范围结果会被移除；整文件结果按定义不包含行范围。`--limit` 必须是正的安全整数，在其他过滤结束后生效；结果仍按级联校准分数排序。

## 历史存储

项目历史文件位于 `<ctx.cwd>/.omp/.cache/find-console/history.json`。插件升级仅替换插件目录，不替换这个文件。写入使用权限为 0600 的临时文件，并通过原子重命名替换；文件不存在时视为空历史。格式损坏时保留原文件并报告问题。遇到未知版本时会报告问题并按空历史处理，后续搜索也不会覆盖原文件。

当前格式为 `{ version: 1, entries: [{ args, searchedAt, within? }] }`。`args` 包含 `query`、`path`、`keywords`、`globs`、`extensions`、`minScore`、`noCache`、`noTranslate`，以及值为 false 的 `help`、`cancel`、`history`。可选的 `limit` 也放在 `args` 中。`searchedAt` 为 Unix 毫秒时间戳。限定文件集合的追问还包含 `within: { query: "<上一条原始查询>", files: ["<绝对路径或 URL>"] }`。完整 JSON 示例见[英文参考](REFERENCE.md#history-storage)。

记录按时间倒序排列，以规范化后的原始查询文本、搜索路径和限定文件集合去重，保留最新参数。最多保留 50 条，包括已完成但没有结果的搜索；取消的搜索不记录。历史存储从版本 1 开始；0.1.0 不写入历史。

宿主命令补全回调没有上下文参数，因此扩展在会话启动、切换时加载绑定项目的历史快照，并在搜索完成后刷新；路径始终来自 `ctx.cwd`。普通查询的补全文本包含全部命令参数。限定文件集合的追问通过宿主历史选择器重跑，避免文本补全意外扩大搜索范围。

## 在结果中继续搜索

操作先关闭当前控制台，通过宿主输入框提出新问题，再使用相同参数重新运行级联和细化。插件仅从当前结果路径及其祖先构造合成目录树。词法扫描和文件列表都通过原生文件系统桥接读取这棵树，不遍历仓库目录。文件内容与元数据仍由原始会话文件系统提供。结果显示上一条原始查询和限定文件数。再次追问只搜索当前结果中的文件；历史记录保存确切的文件限制，以供重跑。
